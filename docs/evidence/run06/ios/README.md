## Implementation and identity

On iPadOS 26, `UIView.edgeInsets(for: .safeArea(cornerAdaptation: .horizontal))` supplies the actual space occupied by window controls. React applies these live leading/trailing insets only to the custom header. Ordinary safe areas still protect the root, while older iOS uses its ordinary local safe-area fallback. No fixed traffic-light padding or device/orientation constants were added. This follows Apple's [custom bar adaptation guidance](https://developer.apple.com/videos/play/wwdc2025/282/) and the API exposed by the installed UIKit SDK.

Non-iOS targets retain a plain wrapper. ## Raster coverage and remaining failure

`node docs/evidence/run06/ios/check-raster.cjs` compares original PNG ink with outlines from the exact bundled fonts, using actual captured tile/viewport frames. It rejects clipped/occluded regions and requires every maximum alphabet symbol/part pair (78), every maximum converter pair (21), default dark long-label converter pairs (12), and concealed/revealed quiz parts at default and maximum size. These required coverage assertions pass.

The [strict gate](raster.log) **fails**: [238 measurements](raster-measurements.json) include 234 within the existing envelope and four repeated maximum-size J main-letter lower-edge misses, in alphabet and converter captures. Each miss is **+2.080301818 physical px**, against the existing **2 px** rounding/antialias envelope. [Machine summary](raster-summary.json) includes every failure; [exclusions](raster-exclusions.json) identify ordinary scroll clipping. No tolerance was widened and no native font or layout change was made to hide the result. Visual legibility does not turn this into a numerical pass.

The raster scale is inferred from the rounded XCTest tile width: 393/110 = 3.572727, matching Run 05's method. It is not an independently read runtime font scale or native baseline. React Native 0.81.5's [default category mapping](https://github.com/facebook/react-native/blob/v0.81.5/React/CoreModules/RCTAccessibilityManager.mm#L271) is 3.571. A [recorded arithmetic sensitivity check](raster-scale-sensitivity.json), keeping measured ink and frame origins fixed, still finds the same four J failures: +2.2224004 px with that source-mapped scale, or +2.1871429 px with the illustrative 25/7 approximation. This does not change the retained gate or its tolerance. Exact-scale closure is not inferred; outer-box/frame rounding and native event baselines still need qualification. The Release build does not expose retained `onTextLayout` baseline state through the standard Hermes debugger. That needs a separately identified Debug build; screenshot ink is not an independently read native event.
