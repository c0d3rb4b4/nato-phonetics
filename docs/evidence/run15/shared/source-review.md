# Scoped implementation review

18 November 2026. Compare changes to actual clean HEAD and the adjacent baseline; preserve all prior findings.

- Native resolves `progressStore.js`; browser build resolves new `.web.js`. No package/lock/provider/permission/native-project/font/tile/layout change. Native policy section arrays equal baseline byte-for-value for Android/iOS; its adapter source is identical. The shared parser's optional generation and injected coordinator are the only progress-engine changes; old native defaults and their existing tests pass.
- Every web mutation uses the same exclusive named lock and reads persisted state inside it. Store-local queue orders hydration/refresh/answer/retry/clear. No cached aggregate overwrites a newer committed record. Missing lock capability never falls back to an uncoordinated write. Timeout rejects without stealing the lock, and pending events survive.
- Clear uses one `setItem` for empty aggregates plus UUID-v4 generation. Failure cannot leave a deleted key without its marker. Both latest read and marker write are under the lock. Earlier pending answers carry an older generation and cannot resurrect cleared totals, even without notifications. Synchronous generation read at explicit submission lets a truly new answer survive an unseen deletion. Current session identity guards still deduplicate, and no recap is imported.
- Successful persistence alone commits data; invalid/future records still fail closed. Generation is optional and validated, preserved by subsequent aggregate writes; old records remain untouched on read. If generation was unreadable at submission, an explicit uncertainty flag keeps pending answers in memory through refresh/Retry; it never guesses a generation, silently drops them or writes across a possible deletion. Recovery guidance explains confirmed Clear and new submissions. No raw response, session identity or tracking data is added. Same-key tombstone is documented in local rules, repository policy and web UI.
- Storage events, pageshow and visible-page changes enqueue read-only refreshes. Notifications are not the correctness barrier; the mutation's latest read/generation comparison is. Browser adapter is one process singleton; its window/document listeners live for that document and disappear on navigation/close. No app render subscribes global duplicate handlers.
- Actual updated-client Edge DOM-handler tests qualify shared storage/lock behavior. The interrupted two-page pointer attempt remains unqualified and unlocalized; it is not attributed to the app or fixed by dispatch changes. Deliberately delayed notification is not an actual suspended-process test. Old code does not cooperate in locks, so deployed legacy upgrade and wider browser qualification remain engineering. Missing capability remains explicit rather than a permanent target exception.
- Documentation/source checks verify current metadata and package commands; hosting headers/atomic deployment/rollback are prepared contracts, not an executed host or unsigned/signed artifact build. P10.3 is current implementation documentation, with re-entry on future recognition/cache/release changes. P10.4–.7/M11 remain open.
