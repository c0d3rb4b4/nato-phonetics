The bounded Android repair is documented in [live-font-scale-diagnosis.md](live-font-scale-diagnosis.md). Earlier cached inverse values reused 36/16/11 SP after a return to reported scale 1 while the current native converter required 24/8/5.5 SP. The repaired adapter consults that converter each time, so the tile keeps the intended uniform dimensions even when native configuration state lags the reported value. The original failed candidate, its exact PNGs/logs and its different loaded-JS bytes remain under [diagnostics/live-scale-reset](diagnostics/live-scale-reset/README.md) and the corresponding artifact directory. They are historical failure evidence, not final passing screenshots.

The converter edge is independently explained in [digit3-fringe-analysis.json](digit3-fringe-analysis.json): row 1162 contains only 6.7–8.2% glyph alpha, and alpha at least 10% begins at row 1163. The actual measured baseline differs by −0.25003 px; Android rounds the requested 19.25 physical-pixel font size to 20. Against that rounded-font outline, strong ink differs by −0.23322 px. This diagnosis does **not** change the original nominal 2.012 px result or silently convert the failing gate into a pass. The remaining numerical case belongs to P05.8.

The larger non-tile issue belongs to P05.2 / P05.8 / R06 / R07: at live 200% and returned 100% settings, the alphabet heading/instruction remains enlarged or clipped and the second instruction clause disappears. The repaired tiles remain complete in those same images. The cold default start restores the full heading and instruction. No native feature-flag override or broad React Native lifecycle workaround was introduced.

Actual Android freeform app-window resizing was not exercised. The [device feature list](device-features.txt) does not advertise `android.software.freeform_window_management`; `wm size` overrides are not claimed as a substitute.
