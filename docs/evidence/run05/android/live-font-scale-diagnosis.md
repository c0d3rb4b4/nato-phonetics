## Source diagnosis and next repair

Source inspection supports a configuration-lifecycle/cache mismatch, but no completed fix is claimed:

- The original `src/lib/tileTextUnits.android.js` cached inverse results by reported fontScale and density. Returning to a previous reported value reused an inverse even when the native converter differed.
- Both `TileTypographyModule` and React Native's `PixelUtil` use `DisplayMetricsHolder`. React Native 0.81.5 `DeviceInfoModule` updates reported font scale during resume separately from the holder. The activity does not handle `fontScale` in `configChanges`, so the Activity can be recreated while the React runtime survives.
- In the installed RN source, `ReactHostImpl.onConfigurationChanged` refreshes the holder only behind `enableFontScaleChangesUpdatingLayout`, which defaults false. `ReactSurfaceImpl` also uses that flag for the layout font multiplier. Text/line/prepared-layout caches account for text attributes and constraints; their measurement equality deliberately ignores the text node tag. Arbitrary text remount keys are not an established cache repair.

After reconciling the fresh-probe evidence, a bounded repair removes only the Android JS inverse memoization. Every text-size and line-height calculation now calls the existing native converter, which uses the same current metrics as React Native's renderer. A focused regression test executes the actual adapter against the observed changing inverse values even when reported scale returns to 1; all three adapter tests, typecheck and lint pass. No native lifecycle or shared web/iOS code was changed.

The repaired candidate completed [1→2→1→2→1](scale-transition-final.log). Independent [raster checks](scale-transition-raster.log) pass 120 actual glyph observations: maximum top-edge error 1.8773 physical pixels and bottom-edge error 1.4870, within the unchanged one-pixel rounding plus one-pixel antialias fringe. [Native geometry and measured baseline checks](native-layout-checks.json) pass 390 baseline observations across the five stages (78 each), maximum error 0.5010 physical pixels against the strict one-pixel baseline limit. The [repaired return-to-default capture](../screenshots/android/alphabet-transition-2-scale1.png) shows readable, correctly sized tile text.

The tile-only conversion change does not repair the renderer's general text lifecycle. P05.2/P05.8 remain open for that engineering follow-up; a tile raster pass is not whole-app accessibility acceptance.

Test whole-app text as well as tiles: compensating tiles against a stale native converter may leave the already-observed navigation/instruction scaling defect unresolved. If the bounded repair fails, the next investigation is to synchronize the holder with current Activity resources before React resumes/re-renders, or use a supported dependency-level fix for RN's font-scale lifecycle and cache invalidation. Neither broader option is implemented.

The [pinned RN startup source](https://github.com/facebook/react-native/blob/v0.81.5/packages/react-native/ReactAndroid/src/main/java/com/facebook/react/defaults/DefaultNewArchitectureEntryPoint.kt) installs its stable flag provider unconditionally; its custom-provider loader is internal. [Public release-level configuration](https://reactnative.dev/docs/release-levels) changes a group of features. No release-channel change, `dangerouslyForceOverride`, accessibility-scaling disablement or arbitrary text-key workaround was applied. Those mechanisms would require a separately reviewed compatibility change, not a claimed local fix.
