# Actual Android split-screen resizing

17 November 2026. **Passed:** real OS split-screen entry, scrolling, divider enlargement and fullscreen restoration retain the converter route and `NUWJ359`. This uses the installed Run 07 JavaScript candidate and unchanged Run 06 native APK identified in [artifact.json](artifact.json).

No display-size simulation, freeform flags or force-resizable setting was used. Android Settings was explicitly opened as the second pane. From the actual Recents screen, the NATO app icon menu offered **Split screen**; selecting it and the Settings task created the pair. The retained UI hierarchies are [Recents](window-recents.xml), [icon menu](window-app-menu.xml) and [pair picker](window-pair-picker.xml).

The initial cold Settings launch exceeded the existing 12-second control wait while only the native root was visible; the bounded readiness retry passed. The first split assertion read the focused **Settings** pane, so UIAutomator did not expose the app input. [Original failure](window-focused-settings.log) is retained; focusing the inert NATO title before dumping repairs that fixture issue. An [intermediate divider attempt](window-resize.log) then retained the half-height pane with an on-screen keyboard visible and failed its complete-tile assertion. This is not counted as a resize pass. Dismissing the keyboard and explicitly dragging the divider produced the subsequent verified larger and restored states. No application fixes or speculative cause are claimed for these fixture interactions.
