# Run 07 Android text-layout diagnostics

17 November 2026. **Neither experiment repaired P05.2, and neither is part of the application.** The installed Run 06 Android APK uses React Native 0.81.5/Fabric. The fixture replaces only its debug React surface through the standard React DevTools renderer `scheduleRoot`; force-stopping and relaunching restores the actual app. Source files, Android startup and dependencies are unchanged by these experiments.

The first [executable fixture](text-scale-probe/run.py) pairs ordinary React Native Text and TextInput controls with a candidate that sets the public `maxFontSizeMultiplier` to current system scale plus one. This ceiling is nonbinding in the tested cases. The fixture includes body text, a heading, explicit-line-height quiz feedback, nested privacy-style text and controlled input. It records native `onTextLayout`/`onContentSizeChange` events, measured native frames, actual screenshots and the component mount count. Seven live stages run 1→2→1→0.85→1.3→2→1 without remounting; separate process launches at 0.85/1/1.3/2 supply uncapped cold references.

`python3 docs/evidence/run07/android/diagnostics/text-scale-probe/run.py` completes; `node .../compare.cjs` exits **1**. [Comparison](text-scale-probe/comparison.json): 22 of 35 cold/live observations fail at the original strict frame/event/raster checks. The candidate changes rendered glyph sizes, but the native frames retain their initial heights. At live 2×, body/feedback/input heights are 57.714/24/47.429 dp versus cold 167.429/72/63.429 dp. The input mount and `NUWJ359` value remain intact. Returned 1× text frames pass; two input comparisons differ in content-size event data despite equal outer frames. This fixture does not establish editable-caret or keyboard acceptance.

[Cold 2× control](text-scale-probe/screenshots/cold-scale2.png) and [live 2× failure](text-scale-probe/screenshots/live-1-scale2.png) show the difference directly: glyphs are enlarged into stale boxes and clip internally. Cold candidate/control outer frames agree at all four tested settings. That validates the proposed ceiling's cold sizing in this bounded sample, **not** its live behavior or a general wrapper contract. An app adapter was therefore not introduced.

The second [bounded fixture](text-scale-probe-yoga/run.py) also changes the candidate's `minHeight` between 1 and 2 dp, below every measured content height. Its [committed JS style observation](text-scale-probe-yoga/live-1-scale2.json) reports `minHeight: 2`, but native frames remain stale. [Comparison](text-scale-probe-yoga/comparison.json): five of ten observations fail; `compare.cjs` exits **1**. No minimum-height or other layout workaround is shipped. This failed variation narrows the investigation but does not prove an exact native cache/dirty-propagation cause.

All 15 retained diagnostic PNGs (11 first-fixture, four second-fixture) were inspected directly. They are real native controls, **not final app screenshots**; the live clipped results are deliberately retained. The `initial-interrupted` folder contains an invalid overlapping harness attempt, including partial screenshots and inspector errors; it is excluded from the 15 and from all acceptance comparisons. The complete single-driver run supersedes it without deleting its diagnostic record.

Relevant primary documentation: React Native defines [maximum font-size multiplier behavior](https://reactnative.dev/docs/text#maxfontsizemultiplier); Android documents [nonlinear font scaling](https://developer.android.com/about/versions/14/features#non-linear-font-scaling). Installed 0.81.5 source inspection confirms the multiplier participates in `TextAttributes` equality/hash, while Android `PixelUtil` applies the system SP conversion and optional ceiling. These facts supported testing the hypothesis; they did not predict the failed live-layout result correctly.
