# Android 11 on a 32-bit phone emulator

The ordinary x86 install of the Run 32 engineering APK passed three converter checkpoints. Forcing the secondary armeabi-v7a ABI on the same universal APK crashed the application during startup. The guest's kernel reports i686 and PackageManager advertises x86, armeabi-v7a and armeabi. Its native bridge is libndk_translation. The published Google APIs image checksum, license comparison, isolated launch and original settings are recorded. The two early x86 commands failed at observer setup. Android 11 returns a failing exit status when `pm path` looks up an absent package. After installation of the test observer, the shell could not traverse the app-specific external files directory to read its readiness signal. The second diagnostic capture shows the running Settings screen. The successful observer accepted `-e evidenceDirectory media` and used its app-owned Android/media directory. It used ordinary shell privileges and recorded the runtime process after React views mounted. The original product, instrumentation manifest and product permissions stayed identical for all three attempts. [First attempt](api30-x86/result.json) · [Second attempt](api30-x86-retry/result.json) · [Observer build](api30-observer-build.json) · [Driver](api30-abi-smoke.py).

The first ordinary ARM launch with `am start -W` exceeded the 55-second host wait. Its crash PID was recovered from logcat. A fresh launch without the wait flag independently reproduced the same error. Re-enter compatibility qualification with a native ARMv7 Android runtime or a device-targeted install from this AAB. Retain the forced universal-APK result separately. The ordinary x86 install passed on this guest. Native ARM hardware prevalence, complete 32-bit screen coverage and final support acceptance are open. The guest returned to its initial package list, font setting, keyboard, display size and density, then shut down. Its isolated download and guest files remain in TEMP. Automatic tool approval rejected recursive cleanup before executing the command. The SDK installation and other running guests were untouched.
