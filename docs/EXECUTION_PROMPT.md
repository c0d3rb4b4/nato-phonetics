# Reusable delivery prompt

Paste the following into Codex in VS Code whenever you want the next implementation batch. It works with either the parent `apps` workspace or the app folder open. The plan contains the detailed execution contract, so this prompt does not need to repeat it.

```text
Work in [nato-phonetics](nato-phonetics/). Read applicable instructions, [DELIVERY_PLAN.md](nato-phonetics/docs/DELIVERY_PLAN.md) and [APP_REVIEW.md](nato-phonetics/docs/APP_REVIEW.md); follow the plan's execution contract. Reconcile code/evidence with current status and priorities; preserve user changes and avoid repeating verified work. Use impact triage and task dependencies to select a feasible batch; forecast effort/risk/verification with no fixed phase count. Implement, test, reforecast and continue eligible work. Bound investigations; park low-impact residuals with evidence and re-entry triggers. Keep human-only work in M11. Update status, ledger, execution record, review and affected docs; never mark unverified work complete. Capture changed-flow screenshots on supported targets per the plan; record missing captures or inapplicability. End with delivered work, checks, evidence/screenshots, residuals, blockers/manual actions, next priority and stop reason.
```

The prompt is **977 ASCII characters**, excluding code fences, deliberately under 1,000 characters. This is a compactness target, not a claimed product limit: a fixed Codex VS Code composer character limit could not be established from the [official IDE documentation](https://learn.chatgpt.com/docs/codex/ide) or targeted inspection of the installed extension, version `26.1021.22027` (16 November 2026). The referenced plan holds the larger instructions outside the pasted prompt, including the [screenshot evidence contract](DELIVERY_PLAN.md#screenshot-evidence-before-the-final-summary).

Priorities come from the plan's latest amendments and current ledger, alongside the review's **Current delivery status**, scope and acceptance criteria. Apply the plan’s impact triage, task-level dependencies, investigation checkpoints and residual re-entry triggers. P3 polish does not automatically block useful independent features; failed checks remain explicit. Historical execution records provide context, with newer amendments taking precedence; reconcile discrepancies with current code and evidence.

Reuse it unchanged after each batch, including after supplying manual results. Progress must be recovered from the current files and evidence, not from an assumed phase number or the previous chat's memory. Reusing the prompt does not authorize publication or mark manual checks complete.
