# Uniform UI design language for NATO Phonetics

Reference and Word Converter set the direction for the whole app. Both put the controls beside the content they affect, use blue to indicate selection or the main action, and keep playback controls and nearby content in place while audio runs. Apply those patterns to navigation, settings, practice and support on Android, iOS and web. Use the pastel phonetic colours for learning content. Use the app theme for general controls and information surfaces.

The audit covers all 13 routes and 12 distinct screens. The root route opens the same Reference screen as `/alphabet`. The current-state findings reflect the shared source and the exported app in light and dark phone layouts, including an entered conversion and all three quiz modes. The proposed design and its verification are tracked under [P05.9 in the delivery plan](DELIVERY_PLAN.md#p059-uniform-ui-design-language).

**22 November 2026.** Runs 34–35 implemented the shared design across the pilot, learning and support routes. Reference and quiz share the compact choices. Converter, Voice Select and typed recall share the field. Learning Progress puts saved totals before the practice action and saved-symbol rows. About and Privacy share destination rows, and Page Not Found provides a primary Site Map action. Installed iOS and the populated Android voice-list check remain open. ## Shared patterns

| Pattern | Design to carry across the app |
| --- | --- |
| Screen and navigation | Keep the safe-area-aware bottom bar in the order Reference, Word Converter, Letter Quiz, Menu. Keep the active destination visible, with Menu selected on its detail screens. Start with the controls or content the user came for. Use a compact title where it identifies a detail screen or an exercise. Reuse the existing screen gutters, spacing and centered reading width, and let content scroll beneath the app chrome. |
| Spacing and type | Start with the current `Screen` defaults of 16 logical units for horizontal gutters and 12 between content groups. Use 8 within a compact row or choice group and reuse the existing 12-unit control radius. Distinguish page titles, section labels, body text and supporting text. Use the current platform UI type for app controls and reserve the bundled tile typography for phonetic cards and bubbles. |
| Choices and actions | Use Reference’s compact labelled choices for short, mutually exclusive options. Give the selected option a clear fill or outline and expose its checked state to assistive technology. Let labels wrap and groups flow onto another line at narrow widths or larger text sizes. Use a blue primary action for the next step, neutral controls for secondary actions, and an explicitly labelled destructive action inside its confirmation. |
| Navigation rows and inputs | Use one compact row for destinations. It can carry an icon, a title, a useful secondary line or current value, and a trailing chevron. Keep action buttons for operations such as Start, Copy or Retry. Reuse the Converter input’s surface, border, radius and visible focus treatment for text fields while respecting the keyboard and input needs of each screen. |
| Playback | Place the shared 48×48 Play/Stop control beside the content it plays. Switch its icon and accessible name in place. Keep current-word and current-card borders inset so they leave text and geometry intact. Preserve Reference play-all and resume, individual tile playback, Converter phrase and token playback, and separate voice selection and preview actions. |
| Focus and feedback | Show keyboard focus independently of checked, playing, pressed and disabled states. Draw focus without changing measured control dimensions. Keep audio failures in dismissible notices with a reachable recovery action. Keep save, retry, empty and offline messages near the affected task and expose their changes accessibly. Use explicit text for outcomes such as Due now, Incorrect and Delete. Let user-requested actions such as expanding Copy or share or advancing a question change the screen intentionally. |

The shared shell, controls and playback components already provide a starting point. Centralize recurring sizes and state styles there as they are reused, then remove screen-specific duplicates. Preserve the tile geometry, font metrics, header/body composition and colour mapping described in the existing tile specification. ## Screen analysis

This table records the observations and proposed changes from the baseline audit.

| Screen | Current design | Change to make |
| --- | --- | --- |
| Reference | Compact sticky Letters/Digits and Play/Stop row above the phonetic cards. Checked and playing states are visible. | Keep this as the control-row and card-grid reference. Extract reusable styles and preserve the selected set, play-all order, resume behavior and inset playback border. [Source](../app/alphabet.js) |
| Word Converter | The sticky input and Play/Stop row leads directly to phonetic bubbles or full cards. Export is available through a disclosure below the output. | Keep this as the input, output and secondary-action reference. Preserve supported-token and omission behavior, pagination, exact Copy/Share output and current-word highlighting without layout shifts. [Source](../app/converter.js) |
| Letter Quiz | Setup uses vertical stacks for mode, symbols, review and length. Most choices share the same visible style whether checked or unchecked. A progress link precedes setup. Active questions already use compact playback controls. | Use visibly selected, wrapping choice groups and short section labels. Put Start round after the choices and treat Learning Progress as a secondary destination. Keep an explicit question prompt and progress, a readable answer state, and a clear Next or Results action. Keep all modes, typed drafts, listening text alternative, concealment, scoring and retry behavior. [Source](../app/letter-quiz.js) |
| Menu | Icon-and-chevron cards establish a useful destination pattern. Tall rows and long descriptions reduce how many destinations fit in the first viewport. The web availability block has its own larger heading and a full-width action. | Use compact destination rows and keep descriptions that help someone choose a destination. Give web availability a compact status section with its relevant update or retry action and keep the waiting-update instructions visible when they apply. [Menu](../app/menu.js) · [Web availability](../src/components/WebOfflineStatus.web.js) |
| Settings | Converter settings already use compact selected rows. Appearance is a vertical list with a tick, Voice splits its action and current value, and Preferences mixes routine navigation with reset information. | Use the Converter choice pattern for Appearance and keep Display, Playback speed and Pause between words readily accessible. Show the current voice in its destination row and use the same row pattern for Audio Help and Learning Progress. Give Reset Preferences a separate group with its scope stated. Reflect saved choices accurately through loading, save failure and reset. [Source](../app/settings.js) |
| Voice Select | Voice rows already have a separate Play/Stop control. The list uses custom selection styling, page-sized locale headings and full-width locale filters. Loading, empty and retry content competes for attention with the picker. | Put System Default, search and locale filtering in a clear order. Reuse the Converter field and compact choice styling. Use small locale section labels and show exactly which voice is saved. Keep selection and preview as separate named controls, and keep load, retry, removed-voice and empty-result states understandable. [Source](../app/voice-select.js) |
| Learning Progress | Introductory and scheduling paragraphs come before the main action or saved symbol list. Counts and symbol details read as continuous text. Clear Progress sits below the saved data. | Lead with saved totals, due and missed counts, then Open practice. Give each saved symbol a compact row with its counts and review state. Place scheduling details in a labelled section or disclosure. Keep explicit delete and cancel actions, pending-write feedback and storage retry. [Source](../app/progress.js) |
| Audio Help | The test already has a square Play/Stop button beside its title. Large headings, long prose blocks and full-width links make troubleshooting slower to scan. | Keep the test at the top. Use smaller section labels and short steps for volume, output and voice troubleshooting. Apply the shared destination rows to Voice Select and Privacy. Preserve the provider, connectivity and microphone wording. [Source](../app/audio-help.js) |
| About | The app name and version identify the screen. Large subsection headings and several full-width buttons give supporting information and links similar visual weight. | Use a compact name/version block, readable feature copy, and shared destination rows for Privacy, Audio Help and external support. Keep the external destination clear and preserve the information about local data and speech providers. [Source](../app/about.js) |
| Privacy Policy | The policy already keeps its update date below the title. Section titles are visually bold text inside paragraphs, with generous repeated margins. | Keep the date and policy text. Use semantic section headings, consistent paragraph spacing, and a readable text width. Keep platform-specific policy content and the support link accessible. [Source](../app/privacy.js) |
| Site Map | The map uses the Menu row pattern at its taller size. Learning Progress is missing, and some descriptions predate listening and typed practice or the Converter settings. | Reuse compact destination rows, add Learning Progress, and update stale descriptions. Keep one entry for Reference and preserve the existing direct URLs. [Source](../app/_sitemap.js) |
| Page Not Found | A heading, one explanation and a Site Map action provide recovery. The bottom bar is already available. | Use the same neutral recovery typography and action styling as other empty or error states. Keep Open site map obvious and leave Reference and Menu reachable through the bottom bar. [Source](../app/+not-found.js) |
