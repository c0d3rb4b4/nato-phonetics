## Recovered design and completed metrics

The original alphabet in `784bb93:app/alphabet.js` defines width 110, height 150 (11:15), radius 12, header 60 including a 2-unit bottom divider, body horizontal/vertical padding 8/12, centered alignment, letter 36/800, word 16/600, word following gap 6 and guide 11/400 italic. Its per-letter colors remain the canonical data palette. It did not define a font family, exact line boxes or baselines. The historical quiz had different dimensions and is not the reference.

V1 completes those missing values with pinned static Nunito-derived faces named **NatoTile** to distinguish the generated static instances. The same three TTF files are packaged on every target. New explicit values are zero letter spacing; letter line 50, word line 22, guide line 16; fixed text boxes and nominal baselines below. Dimensions are React Native logical units / browser CSS pixels at default 16 px root text size. All boxes are relative to the tile's top-left. Rounded corners and pastel backgrounds are retained in both themes; foreground is `#1F2933`, guide `#374151`, divider `rgba(0,0,0,0.1)`.

The word/guide group is 44 units high (22+6+16), centered within the 90-unit body. Body padding is accounted for by those boxes, not added a second time. The header's 50-unit line is centered within 58 units above the divider. Nominal baselines follow the pinned font's ascent 1011/descent −353 at 1000 units/em, with extra line space distributed equally: `y + (lineHeight − size × 1.364)/2 + size × 1.011`. These are **specified baseline targets**, not claims that native raster measurements have passed. Each text run now sits inside the fixed outer box and is aligned to that shared baseline using an actual layout measurement: native `onTextLayout` reports line y+ascender; web measures an empty inline baseline marker. On native, Run 07 also reads the actual parent and outer-box origins from `onLayout`: Yoga can round those positions independently. The correction targets `specified tile baseline × scale − actual parent Y − actual box Y − native line baseline`, retaining geometry across symbol changes while rejecting old-size/unmounted callbacks. A vertical translation corrects the inner run only; font identity, size, line height and the outer box stay unchanged. This corrects the observed browser baseline quantization (for example 40 CSS px versus the 40.844 target at default size) rather than relaxing the tolerance at high pixel density. Platform text rendering must still be measured against the target after correction; any material discrepancy stays open under P05.8.

Run 05 measured the baseline correction on web and native targets, with the platform evidence retaining scope and rounding results. **Android live 2×→1× scaling exposed a failing case:** tile geometry returned to default but glyphs remained enlarged/clipped, even when retained native baseline events matched the nominal targets. Run 06's final Android candidate handles font-scale changes without remounting the active screen, refreshes native display metrics and DeviceInfo, and passes repeated live tile raster checks. Complete ordinary instruction text remains visible, but its glyph size stays at the previous scale; P05.2 is still open. Earlier clipped ordinary text belongs to historical/diagnostic candidates. See [current Android evidence](evidence/run06/android/README.md); the tile contract and strict tolerance are unchanged.

The historical guide foreground `#4A5568` fails 4.5:1 small-text contrast on Charlie and digit 2 (both 4.194:1), Romeo (4.415:1) and Hotel (4.441:1). V1 uses the previously maintained accessible foreground `#374151` for the italic guide, preserving every per-letter background. This is an explicit accessibility correction to the historical color. No labels wrap, truncate, ellipsize or auto-shrink. The longest word November measures 75.712 units at 16; Uniform's guide measures 73.414 at 11, both within 94. These values are advance widths before kerning; the all-letter/digit font test and actual browser/native checks own verification. Header and text positions do not change by route, theme, platform or breakpoint. Quiz concealment omits the word and pronunciation nodes entirely, leaving the same empty body geometry; instructions and feedback appear outside the tile. Focus and press use internal border overlays and cannot change tile bounds or colors. Pressed opacity dimming is deliberately excluded: at 0.85 it would lower small-guide contrast below 4.5:1 on some light-theme tiles. There is no scaling or motion during press.

The historical card also supplied platform-dependent shadow hints (black, opacity .15, radius 8, offset 0/4, Android elevation 5). Those are not used as geometry or typography; v1 omits the decorative shadow so edge and text comparisons have an unambiguous common boundary. This is an explicit reversible completion decision, not a claim of recovered universal raster styling.

## Scaling, layout and accessibility

`TileGrid` supplies one `contextScale`, default 1. All present contexts (alphabet, converter and quiz) use 1. Any future context size must change this single grid value. It uniformly multiplies width, height, radius, divider, all text bounds, sizes and line heights; individual overrides are not exposed. The gap between separate tiles is surrounding layout (12), not part of the tile composition. Rows center; a partial final row never stretches.

Native geometry multiplies `contextScale × useWindowDimensions().fontScale`; `allowFontScaling` remains **true**. iOS text multiplies only `contextScale`, allowing native accessibility scaling exactly once. Android 14+ applies nonlinear SP scaling: an actual Android 200% capture in Run 05 showed a 220×300 tile while its large letter grew much less than 2×. The Android-only `TileTypography` adapter therefore inverts the platform's SP conversion for each desired uniform DIP font-size and line-height, using [TypedValue.deriveDimension](https://developer.android.com/reference/android/util/TypedValue#deriveDimension(int,float,android.util.DisplayMetrics)) on API 34+ and the linear scaled-density inverse earlier. React Native then applies its normal SP scaling. This preserves enabled accessibility scaling and produces the intended uniform composition when native configuration and the inverse agree; it does not claim that ordinary Android text scales linearly. The inverse is recalculated for every call: a reported `Dimensions.fontScale` can return to 1 while the renderer still uses its previous converter, so memoizing by reported scale/density is invalid. The repeated live-transition tile checks pass after removing that cache; non-tile text still needs a separate lifecycle repair. Web uses a 1rem ResizeObserver probe against the default 16 px root; changing root text size to 200% doubles both text and geometry. Browser zoom is also supported by ordinary CSS layout. A legacy test that overwrote each text node's font size independently was incompatible with a whole-tile contract; the revised test enlarges root text and verifies actual doubled tile text. It still enlarges non-tile fixed-pixel controls separately.

The available grid width controls column count. Enlarged tiles cause fewer columns and vertical scrolling. When one tile becomes wider than the viewport, the grid's horizontal ScrollView keeps the entire composition reachable rather than clipping it or shrinking text. Native orientation is unlocked for portrait and both landscape directions. M11.4 must still assess real assistive technology, focus/reading order and physical-device reachability at the largest device accessibility setting.

## Font provenance, loading and regeneration

Source: [googlefonts/nunito](https://github.com/googlefonts/nunito/tree/8c6a9bb9732545b9ed53f29ec5e1ab0ff53c4e6f), pinned revision `8c6a9bb9732545b9ed53f29ec5e1ab0ff53c4e6f`, under the bundled [SIL Open Font License](../assets/fonts/OFL-Nunito.txt). [`manifest.json`](../assets/fonts/manifest.json) records actual output/source hashes, weights, metadata and representative advances. Font outlines are instantiated at weight 800/600 from `Nunito[wght].ttf`, and 400 from `Nunito-Italic[wght].ttf`; the name tables are changed to the three explicit NatoTile face names. No synthetic bold/italic or platform font fallback is intended.

Web imports the TTFs into the independent bundle and loads all three through `FontFace.load()` before showing the tile grid. A failed load displays an explicit reload message. iOS includes the same files in Xcode resources and UIAppFonts; startup checks `UIFont(name:)` resolves each exact PostScript name before React starts. Android loads each exact asset and registers it in the matching ReactFontManager style cache before React starts. Missing native assets fail explicitly at startup rather than silently rendering a system font. Packaging/hash and actual runtime font checks remain part of verification; build success alone does not prove identical baselines.

The files are checked in; normal install/build requires no font tool or network font service. To reproduce static files, use Python with fontTools 4.60.2 in an isolated environment. Download the two source files from that pinned revision into a directory as `Nunito.ttf` and `Nunito-Italic.ttf`, then run `python assets/fonts/generate-static-fonts.py <source-directory>`. The generator preserves the source timestamp (`recalcTimestamp=False`) for reproducible output. Review any output hash changes and copy updated files to Android's `app/src/main/assets/fonts`; iOS references the shared asset directory directly. Do not regenerate from an unpinned upstream branch.

## Fidelity verification and human comparison

Automated evidence must identify candidate/source manifest, packaged font hashes, running platform/version, viewport, density, orientation, theme and text scale. Measure every tile's root/header/text boxes against the table after dividing by its one scale factor. Verify all 26 letters, digits when shown, both themes, long labels, complete/incomplete rows, all contexts and concealed/revealed quiz states. Verify real text dimensions in addition to inspecting style properties.

Use at most one physical pixel for edge/baseline rounding at a given density, with an additional explicit one-physical-pixel glyph-antialias fringe when inspecting raster ink. The logical ratio and typography must not drift to accommodate a platform. Visual baselines are platform-specific because antialiasing differs; an all-white/blank screenshot, wrong font, changed line count, extra text clipping or shifted layout is never an acceptable raster tolerance. Record failures rather than widening tolerances around them. React Native’s Android text renderer rounds the converted SP font size up to a physical pixel; actual observed deviation must be disclosed and assessed under P05.8. The iOS Fabric font utility multiplies the custom face size without the older renderer’s integer font-size rounding; do not infer a rounding failure there without measured evidence.
