Run 13 introduces a separate `nato.progress.v1` AsyncStorage record (browser storage on web). No account, backend, analytics, provider, permission or dependency is added. All 36 canonical letters/digits share per-symbol attempts, errors, scheduling step, last-review and next-due timestamps. Every guarded accepted submission counts once, across choice/listening/typed modes, partial rounds and Retry Mistakes. Listening text alternatives count equally. This is a simple practice aid, not a measured learning or mastery score.

The record never contains typed answers, mode, practice set, raw audio, full sessions, recaps or question identities. Active rounds/drafts/recaps remain memory-only. Returning via Menu retains them; closing/reloading clears them. Saved totals survive restart. Appearance/voice/pace use the existing preference key and are independent.

After a wrong answer, review is due immediately and the scheduling step resets to zero. Consecutive correct answers schedule review after **1, 3, 7, 14, then 30 elapsed days**; later correct answers retain the 30-day interval. Each day is 86,400,000 milliseconds from the answer's device-clock timestamp. There is no midnight rollover or timezone/DST-based interval. Local display dates follow the device locale. Moving the clock forward/back changes which timestamps are due; no trusted server time exists. Due counts refresh on screen focus, foreground and every minute while focused; a round's symbols are fixed at Start.

In Letter Quiz choose a symbol set, then Full symbol set, Due review or Focus on mistakes. Due includes previously practised selected symbols with `dueAt <= now`; Focus includes selected symbols whose most recent saved answer was incorrect. Both exclude unpractised symbols, which remain in full practice. A later correct answer removes a symbol from Focus and schedules it forward, while retaining lifetime errors. Review length is capped at the available unique symbols, with no repeats. The shared P07 engine shuffles that set, so ordered due selection does not imply an oldest-first question presentation. Empty lists explain how to return to full practice. Existing mode/score/Retry/audio rules apply.

Reads validate the whole versioned record, canonical keys, finite bounded counters/timestamps, fields and schedule consistency. There was no prior progress schema/key; absent data starts empty v1 without a write. Preference migration is unchanged. Unsupported/corrupt progress stays untouched, with a retry/deletion message; it is never silently reset or partially imported. A future schema requires an explicit decoder/migration and failure tests before writing that schema. Read-only browsing does not rewrite old records.

Writes are serialized with hydration, Retry and Clear. The displayed summary commits only after a successful write. A write failure retains pending events in memory and exposes Retry progress storage; retry applies each once. The opaque guarded question identity prevents repeated clicks/blur/recap rerenders from duplicating counts. Partial-answer persistence does not depend on finishing a round. No response string is passed to storage. Run 15 adds a web adapter: updated same-origin windows take one exclusive Web Lock and re-read the latest record inside each mutation. Interleaved/simultaneous answers merge instead of replacing cached totals. Storage events, page restoration and returning to a visible window refresh committed summaries. A five-second lock wait fails without stealing the lock; Retry retains the pending answer. HTTPS (or secure localhost) and browser Web Locks are required for persistence. When unavailable, practice remains usable with explicit guidance and memory-only pending answers; no unsafe concurrent-write fallback is used. Native keeps its existing process-local adapter.

Menu and Settings link to Learning progress, showing saved totals, coverage, due/last-miss counts and each practised symbol. **Clear Progress** requires confirmation, then deletes all saved symbol aggregates and prior pending events. Native removes the key. Web atomically writes an empty symbol map with a fresh UUID-v4 `generation` marker in the same v1 record; no second key or split delete/marker write is used. Later writes keep that marker. Pending answers carry the generation observed at submission; an older generation is discarded on refresh/Retry, even if its window received no storage event. New submissions read the current generation before queuing, so an unseen deletion does not discard newly submitted answers. The marker stores no user/answer identity and changes at every deletion. An in-flight earlier write completes before deletion; answers submitted afterward create new progress. The current memory-only round/recap remains, and its earlier answers are not saved again. Failed deletion preserves saved/pending data. **Reset Preferences** changes only appearance/voice/pace and keeps progress. Clearing browser/app storage or deleting installation data is broader; backups have separate controls. See [privacy](../PRIVACY.md).

Automated source/storage/date/browser and actual installed native evidence is in [Run 13](evidence/run13/README.md). The inherited Android live-size readability and original iOS long-drag failures remain engineering gates. Physical AT, interruption/learning usability, backup/provider/policy and release acceptance remain unperformed in M11; batch screenshots do not close P10.7.
